::: Changelog for equivalentPropertyMerger.js :::
- Moved entire file's functionality to parser.js as it was only used there

- Renamed M3 to M4

- Added two sets to M4 which stores IDs of all properties' domains and ranges (called `domainIDs` and `rangeIDs`) and restructured the code to take advantage of these sets.
  Change benefits:
    - M4's worst-case runtime improves from O(n^2) to O(n), where:
		- n is unfilteredProperties (high impact, average)


::: Changelog for graph.js :::
- Renamed A2 to A3

- Renamed A1 to A4

- Changed A3 from an array to a set.
  Reason: A3 was already used as an inefficient set in M1 as follows: for each element E, iterate through all elements in A2 (using `indexOf`) and check if E is there. If not, add E to A3.
  Change benefits:
	- M1's worst-case runtime improves from O(n^2) to O(n*(u+v)), where:
		- n is an array of strings (node IDs) which should have a pulsating halo (low impact, average)
		- u is the runtime of `get()` of Map 
		- v is the runtime of `add()` of Set 

- Restructured code of M2 to take advantage of the new maps generated by parser.js in addition to reducing duplicate code in M2 which comes from M1
  Reason: This allows better performance and a slightly cleaner codebase
  Change benefits:
	- M2's worst-case runtime improves from O(n+m*(k+p)) to O(n+m*g), where:
		- n is an array of all nodeIDs to highlight (low impact, average)
		- m is an array of missedIDs to highlight (low impact, average)
		- k is unfilteredNodes (high impact, average)
		- p is unfilteredProperties (high impact, average)
		- g is the runtime of `get()` of Map
		
- Replaced A5 with M5
  Reason: A5 was used to index A3 as an array. This is not possible with the new A3 which is a set. Converting the set to an array and index it the old way would defeat part of the purpose of having the set
  Change benefits:
	- Preserve change benefits of A3 change
	- One less stateful attribute to keep track of
